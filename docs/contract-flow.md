# 전자계약 플로우 (현재 화면 기준)

> 마지막 업데이트: 2026-06-12
> 대상 화면: `/admin/contracts`, `/admin/contracts/[id]`, `/mypage/contracts`, `/mypage/contracts/[id]`
> 현재는 모두 mock 데이터(`src/lib/contracts.ts`) 기반 로컬 상태(`useState`)로 동작하며, 실제 모두싸인 API 연동은 아직 없음.

---

## 1. 기본 개념

| 항목 | 값 |
|------|----|
| 계약 유형 (`ContractType`) | 렌탈 / 위탁 / 매입 |
| 계약 상태 (`ContractStatus`) | 작성중 → 서명 대기 → 서명 완료 / 만료 / 취소됨 |
| 전자서명 수단 | 모두싸인(Modusign) 링크 단일 방식 |
| 계약 템플릿 | tmpl001 렌탈 서비스 이용 약정서 / tmpl002 위탁 계약서 / tmpl003 매입 계약서 |

각 템플릿은 계약 유형(`contractType`)에 1:1로 매칭되고, 계약 본문(`CONTRACT_BODY`)과 입력 필드 목록(`fields`)을 갖는다.

---

## 2. 전체 흐름 요약

```
[운영자]                                  [회원/서명자]
계약 발송 모달에서 정보 입력
  → 계약 생성 (작성중 or 바로 서명대기)
  → "발송" 클릭
  → 상태: 서명 대기, 모두싸인 링크 발송      → 마이페이지 "계약서" 목록에 노출
                                          → 계약서 상세에서 본문/필드 확인
                                          → "모두싸인에서 서명하기" 클릭
  ← 상태: 서명 완료로 자동 반영              → 서명 완료
```

서명 대기 중 기한 내 서명이 없으면 상태가 "만료"로 바뀌고, 운영자는 "재발송"으로 다시 서명 요청을 보낼 수 있다. 운영자가 직접 "취소"하면 "취소됨"으로 종료된다.

---

## 3. 운영자 화면 (`/admin/contracts`)

### 3.1 계약 현황 탭

상태별 필터(전체/작성중/서명 대기/서명 완료/만료/취소됨)로 목록을 조회하고, 상태별로 다른 액션 버튼이 노출된다.

| 상태 | 가능한 액션 | 설명 |
|------|------------|------|
| 작성중 | 수정 / **발송** / 삭제 | `handleQuickSend` — 상태를 "서명 대기"로 바꾸고 `sentAt`을 오늘로, `signatureExpiry`가 없으면 +14일로 설정 |
| 서명 대기 | 보기 / **재발송** / 취소 | `handleResend` — `sentAt` 갱신, `completedAt` 초기화, `signatureExpiry`를 오늘+14일로 재설정 |
| 서명 완료 | 보기 / **PDF 다운로드** | `handleDownload` — 현재는 토스트만 표시, 실제 다운로드 없음 |
| 만료 | 보기 / **재발송** | 서명 대기와 동일한 `handleResend` 호출 |
| 취소됨 | 보기 | 종료 상태, 추가 액션 없음 |

### 3.2 계약 발송 모달 (`+ 계약 발송`)

새 계약을 만들거나(`editingId === null`) 기존 "작성중" 계약을 이어서 작성(`openEditDraft`)할 때 사용하는 단일 모달. 단계: **입력 폼 → 미리보기 → 발송**.

입력 폼은 A~F 섹션으로 구성:

- **A. 수신 회원** — 회원 선택 시 이름/이메일/연락처 자동 표시
- **B. 연결 대상** — 선택한 회원의 주문/렌탈 건(`LINKABLE_REFS`) 중 상품 → 주문 선택
- **C. 계약 템플릿** — 활성화(`active: true`)된 템플릿만 선택 가능
- **D. 계약 정보 입력** — 선택한 템플릿의 `fields` 목록을 기준으로 동적 입력폼 생성 (필수 항목 `*`)
- **E. 서명 설정** — 서명 만료일 지정 (모두싸인 링크 만료일에 대응)
- **F. 메시지 / 내부 메모** — 서명자에게 보낼 안내 문구 + 운영팀 내부 메모

"미리보기" 버튼으로 계약서 PDF 형태(본문 + 입력값)와 수신 회원/연결 상품/입력 정보 요약을 확인한 뒤 "발송"을 누르면 `handleSend()`가 실행되어 계약이 생성/갱신되고 상태가 "서명 대기"로 바뀐다.

필수 입력값이 모두 채워지고 서명 만료일이 지정되어야(`canProceed`) 미리보기/발송 버튼이 활성화된다.

### 3.3 계약 상세 페이지 (`/admin/contracts/[id]`)

계약 메타 정보(유형/수신회원/연결상품/템플릿/발송일/완료일/만료일), 서명자에게 보낸 메시지, 내부 메모, 계약서 본문(필드 값 포함), 입력값 목록을 읽기 전용으로 보여준다. "서명 완료" 상태면 서명 완료 배너가 표시된다.

### 3.4 템플릿 관리 탭

운영팀이 사용하는 영역으로, 계약 유형별 템플릿(렌탈/위탁/매입 3종)을 카드로 보여준다. 각 카드에는 모두싸인 템플릿 ID, 필드 매핑 상태("완료"/"미완료"), 버전, 최종 수정일과 함께 등록된 필드 매핑 목록(계약서 필드명 ↔ 모두싸인 필드 키)이 태그로 표시되고, 미리보기 / 수정 / 활성·비활성 전환이 가능하다.

"새 템플릿 등록"에서는 템플릿 이름·계약 유형·설명·모두싸인 템플릿 ID·서명자 역할명·사용 여부·PDF와 함께, 계약서 필드명/모두싸인 필드 키/우리 서비스 데이터/필수 여부로 구성된 **필드 매핑 정보** 테이블을 행 단위로 추가·삭제할 수 있다. 모든 행에 계약서 필드명과 모두싸인 필드 키가 채워지면 `fieldMappingStatus`가 "완료"로 표시된다.

> ⚠️ 모두싸인 필드 키는 모두싸인 템플릿 빌더에서 정의한 값으로, 일반 운영자가 알기 어려운 정보다. 이 화면은 해당 키를 직접 다룰 수 있는 운영팀 전용으로 한정하고, 일반 사장님 어드민에는 노출하지 않는 것이 맞다.

## 4. 회원 화면 (`/mypage/contracts`)

- **목록**: "작성중" 상태는 노출하지 않음. "서명 대기" 건은 상단 "서명 필요" 섹션에, 나머지는 "계약 내역"에 표시. "서명 완료" 건만 상세로 진입 가능.
- **상세** (`/mypage/contracts/[id]`): 계약서 본문 + 입력값을 그대로 보여주고, "서명 대기" 상태에서는 "모두싸인에서 서명하기" 버튼이 노출됨. 클릭 시(`handleSign`) 로컬 상태에서 상태를 "서명 완료"로 바꾸고 완료 화면을 표시.

## 5. 실제 연동(모두싸인) 시 추가로 필요한 것

현재 발송/재발송/PDF 다운로드/서명 버튼은 모두 mock 상태 전이 또는 토스트일 뿐이며, 실제 구현 시 아래가 필요하다.

| 기능 | 현재(mock) | 실제 구현 시 |
|------|-----------|-------------|
| 발송 | 로컬 상태만 "서명 대기"로 변경 | 입력값을 템플릿의 모두싸인 필드 매핑에 맞춰 모두싸인 "문서 생성+서명요청" API 호출 → 응답으로 받은 문서ID/서명 만료일을 계약에 저장 |
| 재발송 | 무조건 상태 리셋 + 만료일 +14일 | 서명 대기(미만료) 중 리마인드면 모두싸인 알림 재전송 API, 만료/취소 후 재발송이면 기존 문서 무효화 후 새 서명요청 생성 |
| 서명 완료 반영 | 회원이 직접 버튼 클릭 시 즉시 반영 | 모두싸인 웹훅(또는 폴링)으로 "서명 대기 → 서명 완료" 동기화, `completedAt` 및 완료 문서 정보 저장 |
| PDF 다운로드 | 토스트만 표시 | 서명 완료 건은 모두싸인 완료문서 다운로드 API를 백엔드에서 프록시, 서명 전 건은 다운로드 비활성화 또는 미서명 미리보기 PDF 제공 |

이를 위해 `Contract` 타입에 `modusignDocumentId`(발송된 모두싸인 문서 식별자), `signedDocumentUrl`(완료 문서 경로) 같은 필드 추가가 필요하다.

| # | 항목 | 질문 |
|---|------|------|
| 1 | 템플릿 등록 시 PDF 업로드 → 모두싸인 연동까지의 운영 프로세스 | 운영팀이 모두싸인 콘솔에서 직접 템플릿을 만들고 이 화면에 결과만 반영하는 별도 백오피스 작업이 필요한지 |

| 3 | 서명 전 계약의 PDF 다운로드 허용 여부 | 미서명 미리보기 PDF를 제공할지, 버튼을 비활성화할지 |
